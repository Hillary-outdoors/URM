HOW TO TELL WHERE THEY GO
-------------------------
Open your repo's main page on github.com and look at the file list.

  If you see  app, components, lib, supabase  listed there
      -> the repo root IS the app.
      -> Upload the CONTENTS of this zip (the folders above), NOT a folder
         called hillary-safety-app. Putting them in a new folder would make a
         second copy and Vercel would keep building the old one.

  If you see a single folder called  hillary-safety-app  (or similar)
      -> open that folder first, then upload the contents inside it.

UPLOADING
---------
1. Repo main page (or the folder above) > Add file > Upload files.
2. Drag in all the extracted folders and loose files at once.
   GitHub keeps the folder paths and overwrites anything with the same name.
3. Write a commit message, e.g. "URMA: six tick boxes, initials, activity requirements".
4. Commit. Vercel redeploys on its own.

ONE THING TO CLEAN UP
---------------------
GitHub's uploader overwrites and adds, but never deletes.
If supabase/08_trial_data_part1.sql and 08_trial_data_part2.sql are still in your
repo, they are the old two-big-files version and have been replaced by 10 to 18.
Delete them in GitHub (open the file > bin icon) or just leave them: they are
plain text and nothing reads them.
